How the score works & what it cannot tell you

Start at 100; subtract 17 per high, 10 per medium and 5 per low warning, with a floor of 0. Grades: A ≥90, B ≥75, C ≥60, D ≥40, F <40. Informational observations do not affect the score.

A single response cannot represent a whole website. CSP presence does not validate policy quality. CORS reflection does not prove data exposure. HTTPS checks do not assess cipher suites. Scores are educational heuristics, not certification.

A LITTLE MORE CLARITY

Good questions.
Clear answers.

Know what the project does before you use it.

Does this website scan real websites?

No. This public demo uses simulated fixtures and never sends requests to a target. The separate Python CLI and local Streamlit dashboard can audit public websites you own or are explicitly authorized to assess.

Do I need to deploy a backend?

No. The public demo is HTML, CSS and JavaScript hosted on GitHub Pages. For live audits, install the Python project locally. Streamlit is only needed for the local dashboard.

Is the audit safe to use?

The tool limits requests and avoids exploitation, but any real GET request contacts a server. Only audit appropriate, authorized pages. Keep the Python dashboard local: its DNS checks are not hardened against DNS rebinding.

What does CyberShield actually check?

HTTPS usage, HSTS, CSP presence, MIME sniffing protection, framing controls, referrer and permissions policies, cookie attributes and limited CORS origin behavior. It reviews the final response of a single page.

Is this a penetration testing tool?

No. It is a response-configuration auditor. It does not verify exploitation, assess every endpoint or provide comprehensive OWASP Top 10 coverage. Findings and scores require application context.

Can I download and share the results?

Yes. The demo exports JSON, HTML and CSV, and supports browser printing or Save as PDF. Simulated reports remain labeled. The local Python tool exports JSON and HTML reports for authorized audits.
